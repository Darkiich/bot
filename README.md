# Мемный бот

- Каждые **20 минут** ищет в интернете случайную картинку по запросу «смешные мемы старые» (Bing Images, запасной — DuckDuckGo), отправляет её в канал `1552011762885197915` и ставит реакции 😂 и 💩.
- Каждые **8 часов** проверяет мемы за прошедший период: у кого есть роль `1552258642835939348` и кто не поставил реакцию, попадает в протокол о правонарушении в том же канале.
- Нарушителям можно включить наказание: их сообщения удаляются и заменяются на 💩 (от их имени и с их аватаркой, через вебхук).

## Команды

Префикс `&` (меняется в `.env`, `PREFIX`). Все команды работают и как `&команда`, и как слэш `/команда`.

Админ-команды доступны ролям/пользователям из `COMMAND_ACCESS_IDS` и администраторам сервера.

| Команда | Кто может | Что делает |
|---|---|---|
| `&punish on` / `&punish off` | доступ | заменять сообщения нарушителей на 💩 / отозвать; без аргумента — показать режим |
| `&violators` | все | список нарушителей и текущий режим |
| `&pardon @участник` | доступ | снять статус нарушителя до следующей проверки |
| `&test [секунды]` | доступ | быстрый тест: мем → ждёт (по умолчанию 60 с) → проверка реакций на этот мем (нарушители не сохраняются) |
| `&check` | доступ | настоящая проверка прямо сейчас |
| `&meme` | доступ | отправить мем сейчас |
| `&help` | все | список команд |

## Настройки (.env)

```env
TOKEN=токен_бота
PREFIX=&
MEME_CHANNEL_ID=1552011762885197915
WATCHED_ROLE_ID=1552258642835939348
MEME_QUERY=смешные мемы старые
MEME_INTERVAL_MINUTES=20
CHECK_INTERVAL_HOURS=8
MIN_REACTED_PERCENT=100
REACTIONS=😂,💩
PUNISH_EMOJI=💩
MEME_ON_STARTUP=true
COMMAND_ACCESS_IDS=1508568035206631645,568092953948454922
```

`TOKEN`, `MEME_CHANNEL_ID`, `WATCHED_ROLE_ID` обязательны, остальное — со значениями по умолчанию как выше.
`MEME_ON_STARTUP=true` — мем сразу при запуске (удобно для проверки).

## Настройка бота в Discord

1. [Developer Portal](https://discord.com/developers/applications) → приложение → **Bot** → включить **Server Members Intent** и **Message Content Intent**.
2. Права бота: просмотр канала, отправка сообщений, прикрепление файлов, добавление реакций, чтение истории, **управление сообщениями**, **управление вебхуками** (scopes `bot` + `applications.commands`).

## Запуск локально

```bash
pip install -r requirements.txt
python main.py
```

Быстрая проверка: запустите бота (при `MEME_ON_STARTUP=true` мем придёт сразу), затем на сервере `&test 30` и поставьте реакцию — через 30 секунд придёт тестовый протокол.

## Хостинг на GitHub Actions

1. Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**: имя `ENV_FILE`, значение — **всё содержимое вашего `.env`** (workflow создаёт из него `.env` на сервере; `MEME_ON_STARTUP` там принудительно `false`).
2. Запушить в `main` — бот стартует сам (или **Actions → Discord bot → Run workflow**).

Как это устроено (`.github/workflows/bot.yml`): джоба на GitHub живёт максимум 6 часов, поэтому бот сам завершается через 5ч45м, а следующий запуск (расписание раз в 3 часа) уже ждёт в очереди и сразу стартует. Одновременно всегда работает только один экземпляр. После пуша новый запуск встаёт в очередь, старый бот замечает его в течение ~2 минут и уступает место. Состояние (`data/state.json`) переносится между запусками через кэш Actions. Если бот падает, он перезапускается через 30 секунд.

Ограничения: для приватного репозитория бесплатно только 2000 минут в месяц (круглосуточно нужно ~44 000), для публичного — без лимита; при переключении между запусками бот бывает офлайн ~1–2 минуты; GitHub выключает расписание в репозитории без активности 60 дней; правила GitHub не рассчитаны на Actions как постоянный хостинг, поэтому для надёжной работы лучше VPS.
